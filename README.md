
# Вебсайт готельного комплексу

Курсовий проєкт із розробки вебзастосунку готельного комплексу з можливістю перегляду номерів, перевірки доступності та онлайн-бронювання без оплати.

## 1. Опис проєкту

Вебзастосунок розроблено з використанням React та Vite.

Сайт містить інформаційні сторінки готельного комплексу, каталог номерів, ресторан, SPA, послуги та систему бронювання.

Основна сутність системи — бронювання номера готелю.

## 2. Використані технології

- React — розробка інтерфейсу.
- Vite — середовище розробки та збирання.
- JavaScript — програмна логіка.
- CSS — оформлення сторінок.
- React Router — навігація.
- Firebase Authentication — анонімна автентифікація гостей.
- Firebase Cloud Firestore — зберігання бронювань і зайнятості номерів.
- Git і GitHub — контроль версій.
- Visual Studio Code — середовище розробки.

## 3. Реалізована функціональність

### Інформаційні сторінки

- Головна сторінка.
- Інформація про готель.
- Каталог номерів.
- Детальна сторінка номера.
- Ресторан і меню.

### Система бронювання

- Вибір категорії номера.

- Перевірка доступності номерів.
- Введення контактних даних гостя.
- Створення бронювання.
- Перегляд власних бронювань.
- Перегляд деталей бронювання.
- Редагування бронювання.
- Скасування бронювання.
- Автоматичне оновлення кількості доступних номерів.

## 4. Архітектура роботи з даними

Для відокремлення інтерфейсу від джерела даних використано адаптерний підхід.

Основні модулі:

- `src/api/bookingsAdapter.js` — вибір джерела даних.
- `src/api/firebaseBookingsAdapter.js` — операції з Firebase Firestore.
- `src/contexts/BookingsContext.jsx` — спільний стан бронювань.
- `src/firebase.js` — ініціалізація Firebase.
- `src/utils/bookingDates.js` — формування дат проживання.
- `src/data/rooms.js` — каталог категорій номерів.

### Фактичне джерело даних

Основним перевіреним джерелом даних у поточній версії є Firebase Cloud Firestore.

Використовуються дві колекції:

**`bookings`**

Зберігає бронювання гостей, зокрема:

- ідентифікатор бронювання;
- ідентифікатор користувача;
- ім'я гостя;
- електронну пошту;
- телефон;
- категорію номера;
- дати заїзду та виїзду;
- інші дані бронювання.

**`roomAvailability`**

Зберігає зайнятість категорій номерів за датами.

Основні поля:

- `roomId` — ідентифікатор категорії;
- `date` — дата;
- `occupied` — кількість зайнятих номерів.

## 5. Контракт адаптера бронювань

| Метод | Призначення |
|---|---|
| `getAll()` | Отримання бронювань поточного гостя |
| `getById(id)` | Отримання бронювання за ідентифікатором |
| `create(data)` | Створення бронювання |
| `update(id, data)` | Оновлення бронювання |
| `delete(id)` | Скасування бронювання |

Операції виконуються асинхронно.

У режимі Firebase для зміни бронювань та обліку зайнятості використовуються транзакції Firestore.

Для оновлення доступності номерів у реальному часі використовується `onSnapshot()`.

## 6. Автентифікація та доступ

Для гостей використовується Firebase Anonymous Authentication.

Кожен гість отримує власний ідентифікатор користувача.

Система дозволяє гостю переглядати, змінювати та видаляти власні бронювання.

Для роботи з усіма записами адміністратор навчального проєкту може використовувати Firebase Console.

Окрема адміністративна панель на сайті не реалізована.

## 7. Налаштування проєкту

### Встановлення залежностей

```powershell
npm install
```

### Налаштування Firebase

Для запуску в режимі Firebase необхідно створити власний Firebase-проєкт, увімкнути:

- Firebase Authentication з анонімним входом;
- Cloud Firestore;
- відповідні правила доступу до колекцій.

У корені проєкту створюється файл `.env.local` з параметрами конфігурації Firebase.

Режим роботи з Firebase задається параметром:

```env
VITE_DATA_MODE=firebase
```

Інші параметри Firebase мають відповідати конфігурації застосунку в `src/firebase.js`.

Файл `.env.local` не додається до Git-репозиторію.

### Запуск

```powershell
npm.cmd run dev
```

Адреса локального застосунку:

```text
http://localhost:5173/
```

### Виробнича збірка

```powershell
npm.cmd run build
```

### Перевірка збірки

```powershell
npm.cmd run preview
```

## 8. Перевірені режими роботи

### Попередній етап — mock

У межах попередніх лабораторних робіт використовувався локальний асинхронний адаптер із збереженням даних у `localStorage`.

Було перевірено CRUD-операції, стани завантаження, обробку помилок та повторне читання даних.

Підготовлений API-адаптер не вважається підтвердженою інтеграцією з реальним серверним API.

### Поточний етап — Firebase

У поточній версії виконано ручну перевірку роботи з Firebase Firestore.

Перевірено:

1. Створення бронювання.
2. Збереження бронювання у Firestore.
3. Відображення власних бронювань.
4. Редагування дат проживання.
5. Скасування бронювання.
6. Звільнення номера після скасування.
7. Облік зайнятості за датами.
8. Відображення зайнятості між різними гостями.
9. Автоматичне оновлення доступності без перезавантаження сторінки.
10. Відмову в бронюванні, коли всі номери категорії зайняті.
11. Відсутність чужих бронювань у списку поточного гостя.

Перевірка виконувалася локально, зокрема з використанням звичайного вікна браузера та режиму інкогніто.
